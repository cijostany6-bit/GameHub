Glossary — every abbreviation in GameHub

GameHub speaks the vocabulary of AWS, Kubernetes and web security, and it uses that vocabulary in the repository rather than only in conversation. This page exists so that no reader — and no interviewer — has to guess what OAC, IMDSv2 or RS256 means here.

Each entry answers three questions: what the abbreviation stands for, where it actually appears in this project, and what it is for. The "where" column is not generic documentation: those are the files you can open.

Scope. This is the vocabulary as used, not a general dictionary. Terms that a reader might expect but that the project does not use are listed at the end, with the reason.

Deliberately not in this project

A glossary is also a promise about what is not claimed. These are absent on purpose:

  • SLA — no availability promise is made. There are internal SLOs and alarms; an SLA would be a contractual claim the architecture cannot support.
  • MTTR / MTBF — there is no incident history yet, so any recovery-time average would be invented.
  • HPA / autoscaling — the kind cluster runs fixed replicas and production is a single t3.micro; autoscaling would be vocabulary without a mechanism.
  • RBAC — Kubernetes role-based access control is not configured; the local cluster is single-user.
  • TTFB / RPS — the load test reports latency percentiles and request counts rather than throughput targets.
  • RDS — planned and documented as future work (see the AWS table), not implemented. The database is a container.
